# CloudNest 用户自带 API 的 AI 功能实施计划

版本：1.0　创建日期：2026-10-18（Asia/Shanghai）

文档性质：历史设计与分阶段实施记录。本文保留制定时的方案、阶段边界与验收记录，包含当时尚未完成的事项，不作为当前功能状态或操作手册。

当前入口、支持范围和费用说明见 [AI 使用说明](ai.md)，部署与恢复见 [部署手册](deployment.md#ai-部署与恢复)，接口见 [API 契约](api.md#ai-api)。后续维护请同步这些现行文档，不将本计划的历史将来时理解为当前待办。

用户已确定的方向：提供用户配置 API 的入口，使用用户自己的模型为云盘增加 AI 功能。本文其余范围、默认参数和技术选择是为执行制定的初始方案；后续调整应在末尾记录，不把建议或计划记成已完成。

## 1. 产品目标与第一版范围

CloudNest 从“保存和管理文件”扩展为“阅读、查找和利用私人资料”。AI 围绕用户选中的文件工作，继续使用现有账号、文件权限和版本体系。

### 1.1 核心约定

1. 每位用户维护自己的 API 连接和模型，调用费用由相应 API 账号承担。
2. 浏览器只访问 CloudNest 后端，由后端解密该用户的密钥并请求模型服务。
3. 不提供平台公共密钥，不在用户连接失败时偷偷切换到其他用户或管理员的连接。
4. 不要求配置 AI 才能使用云盘；关闭 AI、供应商故障或调用超时不影响上传、下载、预览和分享。
5. 第一版只分析当前用户自己的、仍可访问的文件。公开分享、收集链接和 WebDAV 不获得 AI 调用入口。
6. 文件内容按用户触发的操作发送到配置的服务。首次使用须说明数据发送对象和范围；不会因为上传文件就自动调用收费模型。
7. 模型回答是辅助结果，展示来源与处理范围；模型不直接执行移动、删除、分享或文件修改。

### 1.2 分期边界

| 版本 | 必须交付 | 本期不包含 |
| --- | --- | --- |
| AI v0.1 | 用户连接与模型配置、测试连接、文档摘要、标签建议、用量记录 | 向量库、多轮问答、OCR、图片理解 |
| AI v0.2 | 单文档多轮问答、来源引用、历史会话、取消和失败恢复 | 跨文件自动搜索、文件操作代理 |
| AI v0.3 | 用户独立向量模型配置、语义搜索、显式建立文件夹知识库、跨文档问答 | 任意工具执行、全站自动索引 |
| AI v0.4 | 版本变化摘要、整理建议；按需求选择 OCR 和图片理解 | 未经确认自动移动或删除 |

先完整验收 v0.1，再推进 v0.2。v0.3 的向量存储选型单独设验证关口，不阻塞前两个版本。

## 2. 现有基础和接入位置

本计划基于 2026-10-18 的只读检查；实施前复核文件是否已发生变化。

| 现有位置 | 能复用的基础 | AI 接入注意点 |
| --- | --- | --- |
| `cloudnest-server/.../file/SearchController.java` | 文本、Office、PDF 正文提取；索引修订号 | 不能直接把截断的索引当成完整文档；需要抽出正文提取服务和位置元数据 |
| `cloudnest-server/.../file/DriveService.java` | 文件归属和可访问状态检查 | 每次读取、执行任务、返回结果、打开引用都要检查 |
| `cloudnest-server/.../file/ContentService.java` | 文件内容读取 | 从已授权对象读取，不能根据用户提交的任意磁盘路径读取 |
| `cloudnest-server/.../security/SecretCipher.java` | AES-GCM 密钥加密 | 可复用算法；增加 AI 专用密钥域、版本标记和轮换设计，不改变旧配置解密行为 |
| `cloudnest-server/.../common/Db.java` | 事务和用户级数据库锁 | 外部模型请求不得放在持有用户锁的事务中 |
| `cloudnest-web/src/components/AccountSecurity.vue` | 账号设置入口 | 新增“AI 设置”页签，组件独立 |
| `cloudnest-web/src/components/PreviewDialog.vue` | 文件预览 | 增加 AI 侧栏；移动端使用抽屉 |
| `cloudnest-web/src/api/index.ts` | Cookie 会话、CSRF、错误显示 | 第一版使用普通任务接口和轮询；不要延长全局请求超时 |
| `docs/api.md`、`docs/openapi.json` | API 文档 | 每个里程碑完成后同步 |

当前正文搜索有约 256K 字符截断、PDF 最多 100 页等边界，且不做扫描 OCR。AI 必须区分完整提取、部分提取、无文本、失败和不支持。

当前最新迁移为 MySQL V11、H2 V10。新增迁移实施时按当时最大版本递增，两套数据库分别编号，不修改已发布迁移。

工作区已有 `.env.example`、`DownloadJobs.java`、`application.yml`、`docker-compose.yml` 未提交修改；实施前识别其归属，不覆盖或顺手合并进 AI 改动。

## 3. 用户体验与配置设计

### 3.1 入口和页面

账号与安全 → AI 设置，包含：功能状态、API 连接、模型配置、默认模型、数据发送说明、使用记录。

预览侧栏包含“摘要”“问答”“标签建议”。未配置时显示“配置自己的 API”，并保留当前文件上下文；配置完成返回后仍需用户点击开始，不自动产生调用。

管理员只能控制站点 AI 是否开启、网络目标策略、并发和保留期限等运行约束。管理员页面不提供普通用户密钥查看或使用入口。

### 3.2 API 连接与模型分离

一个连接代表一组“地址 + 凭据 + 协议”，一个连接可以配置多个模型；一个模型有明确用途。聊天与向量模型可以来自不同连接。

| 连接字段 | 约束与行为 |
| --- | --- |
| 显示名称 | 必填，1～60 字符，如“我的模型服务” |
| 协议 | v0.1 固定 `OPENAI_COMPATIBLE_CHAT`，指 Chat Completions 兼容协议，不意味着支持所有厂商原生协议 |
| API 根地址 | 必填，最长 2048 字符，采用包含版本路径的根地址，如 `https://provider.example/v1` |
| API Key | 创建公网连接时必填；保存后只显示“已设置”，不回显明文或密文 |
| 启用状态 | 停用后禁止新任务；撤销或删除连接时取消关联任务并清除运行中的凭据引用 |
| 测试状态 | 未测试、成功、失败；保存不自动发起网络请求；关键字段变化后标记未测试 |

URL 契约：`.../v1` 与 `.../v1/` 归一化为同一个根地址；调用聊天时只追加一次 `/chat/completions`。不接受完整 `/chat/completions` 地址，不自动猜测或补 `/v1`。允许网关的额外路径前缀。

编辑密钥采用明确语义：PATCH 中省略 `apiKey` 表示保留；提交非空值表示替换；空字符串拒绝。删除凭据使用专门操作并同时停用连接，避免表单空值误删。更换主机或根路径必须重新输入密钥，禁止将原密钥直接发送到新地址。

模型字段：所属连接、显示名称、实际模型 ID（最长 200 字符）、用途 `CHAT` / `EMBEDDING`、上下文窗口、最大输出、启用状态、输出上限参数模式、可选温度支持开关。v0.1 只开放 CHAT；EMBEDDING 在 v0.3 实现。

模型名称允许手动输入，不硬编码供应商型号；模型列表获取是后续便利功能，不是保存和使用前提。第一版不开放任意 HTTP Header、任意请求体和任意 API 路径。

模型上下文参数不能仅信任用户填写。实际输入还受站点上限约束；供应商拒绝时说明如何调整，不自动提高限制或换模型。默认不发送 temperature；输出上限参数由已测试的兼容模式决定，首版支持明确选择 `max_tokens` / `max_completion_tokens`，不在失败后自动重发两种请求。

### 3.3 连接测试

1. 先保存配置，再显式点击“测试聊天模型”；按钮说明可能产生少量费用。
2. 测试固定、极短且不含用户文件的提示词；限制输出，不上传目录、文件名或历史对话。
3. 测试走正式调用相同的 URL 校验、密钥隔离、并发和超时策略。
4. 区分：地址被站点策略阻止、连接/TLS 失败、认证失败、模型不存在、接口格式不兼容、额度不足或上游限流。
5. 返回标准错误码、脱敏解释、延迟和供应商实际返回的用量；不返回原始请求头或整段上游错误体。
6. 成功只证明当前配置完成一次指定调用，不宣称其他模型、流式输出、工具调用或向量能力可用。

### 3.4 数据发送与费用提示

首次使用显示当前服务域名、模型、将发送的数据类型、由该 API 账号承担费用。用户同意后记录同意版本与连接目的地指纹；目的地变化须重新同意。

每次文档操作展示文件名、范围、模型、完整/部分提取状态。跨文件或知识库首次索引时还要展示文件数量及聊天、向量服务各自目的地。

用户提供 API Key 不代表浏览器端独占密钥：CloudNest 服务器处理调用时可以解密，服务端运维者具有技术上的访问能力。界面说明这个信任边界，不宣称端到端加密。用户可随时在原供应商撤销密钥。

## 4. 模型调用架构

### 4.1 第一版技术路线

新增独立 `com.cloudnest.ai` 包和 `ModelGateway` 接口。第一版优先使用项目已有 OkHttp 实现窄范围兼容适配器，控制请求路径、DNS、超时、响应大小和动态用户凭据，不额外引入整套 AI 框架。

接口按能力区分 `chat`、未来的 `embed`。业务服务只传入任务、模型配置快照和经过授权的内容，不接触具体供应商请求格式。密钥只在调用层短暂解密；不能写进任务、缓存或异常。

后续 RAG 可评估 Spring AI 的检索和模型抽象，但只有在动态凭据、网络目标控制、依赖兼容性验证后引入；不能同时维护两套重复调用通道。

### 4.2 建议模块职责

| 模块 | 职责 |
| --- | --- |
| `AiConnectionService` / Controller | 当前用户连接、凭据、模型、默认设置 |
| `AiOutboundPolicy` | URL 解析、目标策略、DNS 与连接 IP 约束 |
| `ModelGateway` / `CompatibleChatGateway` | 请求映射、响应解析、能力和错误归一化 |
| `DocumentExtractionService` | 从文件提取文本块、位置、覆盖范围；供检索和 AI 共用 |
| `AiTaskService` / Worker | 持久任务、幂等、取消、并发和恢复 |
| `AiSummaryService` | 分段摘要与合并、摘要缓存 |
| `AiConversationService` | 问答上下文、消息、引用和历史 |
| `AiUsageService` | 实际/估计用量、次数上限、统计 |
| `AiRetentionService` | 到期删除、文件删除关联清理、取消过期任务 |
| `AiEmbeddingService` / `AiRetrievalService` | v0.3 再增加，不能提前留空实现冒充完成 |

前端新增 `AiSettings.vue`、`AiPanel.vue`、`AiUsage.vue`、`AiCitations.vue` 和 `api/ai.ts`。不继续把 AI 逻辑堆到 `DriveView.vue` 或 `AccountSecurity.vue`。

## 5. 密钥、网络和权限边界

### 5.1 密钥生命周期

- 使用带认证的加密保存；为 AI 派生独立用途密钥并保存加密版本/keyId，兼容已有 SecretCipher 的备份模式。
- API 查询只返回 `keyConfigured`；数据库密文也不返回。密钥不写入 localStorage、sessionStorage、URL、访问日志、审计字段、任务消息和浏览器错误上报。
- 前端仅在输入和提交期间持有明文，成功或关闭表单后清空。
- 连接对象、缓存和请求上下文必须绑定 userId；禁止修改全局单例的 API Key 来切换用户。
- 删除凭据后清除可用密文；备份中可能仍存在旧密文，说明保留周期及在供应商处撤销的方法，不承诺历史备份即时擦除。
- 备份恢复必须同时恢复对应加密根密钥；密钥不匹配时明确报错且不覆盖原密文。
- 轮换采用新 keyId 加密、旧 keyId 可读、逐批重加密、完成验证后退役旧密钥；初版至少有测试覆盖的密钥版本设计和恢复操作文档。

### 5.2 用户自定义地址的网络策略

这是开放用户 API 地址的必要实现，不可只使用 URL 正则或请求前解析一次 DNS。

1. 默认仅允许 HTTPS 公网目标和 443 端口，TLS 证书正常校验；额外端口由管理员精确配置。
2. 拒绝 URL 用户信息、query、fragment、控制字符；规范化主机、端口和路径。禁止把密钥放在 URL。
3. 公网模式拒绝环回、私网、链路本地、云元数据、未指定、多播、保留地址及其 IPv6/IPv4 映射形式。
4. 校验全部解析结果；混合公网与受限 IP 的解析结果不能择一绕过。实际 HTTP 客户端只能连接本次验证通过的 IP，保留正确 Host、SNI 和证书校验。
5. 禁止自动跳转；3xx 作为配置错误返回，不把 Authorization 转发到跳转目标。
6. 禁止未经策略控制的系统代理、自动回退、重定向重试路径；连接池按目的地和策略版本隔离，策略更新后淘汰旧池。
7. 单独的管理员配置支持本地模型：只允许明确的主机/IP、端口和地址范围；普通用户只能选择管理员创建的端点别名，不能自己放开内网。
8. 无密钥的本地端点仅在管理员显式允许该端点时可用；公网连接不默认开放匿名代理。
9. 本地 HTTP 仅限明确批准的端点，并在界面说明；不得用“允许内网”大开关放行整个私网。
10. DNS 重绑定、IPv6、跳转和连接池复用必须有自动化测试。测试连接也不能绕过策略。

说明：容器中的 localhost 是容器自身；服务器端无法直接访问用户个人电脑上的模型，除非已配置可达网络。设置页应解释这一点。

### 5.3 内容、引用和操作权限

- userId 只从登录会话取得，不接受前端指定。资源查询同时约束所有者，不依赖难猜的 ID。
- 任务入队、开始、每次外发、结果发布和结果读取都检查文件当前可见性与绑定修订号。
- 账号停用、连接停用/撤销、文件进入回收站或修订变化时，不继续外发旧资料；未完成任务取消或标记过期。
- 已经发给供应商的数据无法收回；停止按钮不承诺供应商停止计费。
- 文档内容属于不可信数据，文档里的“忽略规则/发送其他文件”等文本不能改变系统范围。
- v0.1～v0.3 不给模型文件操作、网络访问或其他工具权限；引用 ID 必须来自本次实际授权的来源集合。
- AI Markdown 走现有净化流程；禁用外部图片自动加载，禁止执行模型返回的 HTML/脚本，不自动访问模型生成的 URL。

## 6. 文档提取、摘要和标签

### 6.1 提取契约

提取结果包含：fileId、revision、内容哈希、提取器版本、状态、块列表、已处理页/字符、总页数（可知时）、是否截断、原因。

块包含稳定 sourceId、文本、序号、位置。PDF 记录页码；Markdown 记录标题和行号；TXT 记录行号；Word 记录段落/标题；表格记录工作表和行区间。不为 Word 伪造分页。

初版优先支持 TXT、Markdown、带文本层 PDF、DOCX。其他 Office 格式先继续原有预览；AI 支持在保留结构的提取测试通过后逐项开放，不能简单剥 HTML 就宣称表格关系可靠。

PDF 扫描件返回 `NO_EXTRACTABLE_TEXT` 并说明尚未支持 OCR；加密、损坏、不支持分别给出原因。不可用空文本生成看似完整的摘要。

第一版沿用现有提取资源上限，统一由提取服务管理。超过上限默认提示选择范围；用户明确选择“仅分析已提取部分”后才继续，结果持续标示“部分内容”。

### 6.2 摘要

输出结构：简短摘要、主要内容要点、关键术语、处理范围。默认中文，允许用户选择跟随原文；不自动添加原文没有的事实。

短文档单次调用；长文档按标题/段落分块，分别摘要后合并。所有子调用分别计入次数与用量。开始前估算调用数量；超过单任务上限时提示缩小范围，不静默多轮循环。

缓存键至少包括 userId、fileId、revision、范围、模型配置版本、连接目的地版本、提示词版本、提取器版本、语言。只在本用户内复用。

有效缓存显示生成时间和模型；“重新生成”明确提示会再次调用。密钥轮换本身可以保留同目的地模型的内容缓存；目的地或模型变化不复用旧结果作为新结果。

### 6.3 标签建议

生成最多 8 个候选标签，遵守现有标签长度上限。模型输出解析失败时返回可理解的错误，不进行隐藏的付费修复重试。

用户勾选后通过现有标签接口保存。保存前重新获取当前标签并展示合并结果，避免覆盖用户刚修改的标签；最终总数不得超过现有 20 个限制。

## 7. 单文档问答和引用

### 7.1 会话语义

创建会话固定 userId、fileId、revision、模型和连接目的地版本。文件发生变化时旧会话只读并显示旧版本标识，继续提问须创建基于新版本的会话。

进入回收站的文件，其 AI 内容和会话暂不可访问；恢复同一修订且仍在保留期内可恢复访问。永久删除时删除派生内容与会话，保留不含正文的用量统计。

删除会话删除其消息、引用和可见答案；不会删除源文件。账号注销清理全部所属 AI 数据。老版本会话不是无限保留的文件备份。

### 7.2 回答过程

1. 后端重新验证会话和文件，读取绑定版本的提取块。
2. 短文档将完整授权范围纳入上下文；长文档先使用本地分块关键词检索选择片段，v0.2 不强制用户配置向量模型。
3. 输入由规则、问题、有限轮历史和来源片段构成；历史只作为对话背景，不当作事实证据。
4. 为输出保留预算，超限时减少历史/片段并标明检索范围，不能截断到破坏编码或段落边界。
5. 模型用来源 ID 引用，后端验证 ID 和位置确实来自本次上下文。无效引用标记或移除，不能转换成任意文件链接。
6. 找不到足够材料时回答“在本次检索的内容中未找到依据”，不能把局部检索未命中表述成全文不存在。
7. 用户点击引用时再次鉴权并定位页码/段落；定位能力未实现时显示原文片段与文件入口，不伪造精确跳转。

v0.2 输出整段结果即可；流式输出为后续体验增强，不作为首轮问答的前置依赖。若加入流式，必须增加事件序号、断线恢复、持久最终状态和代理缓冲配置。

## 8. 任务、取消、幂等与资源控制

### 8.1 持久任务状态

`QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED / STALE`。

任务记录执行阶段、已完成子调用数、总子调用数（已知时）、心跳和终态原因。没有可靠总量时显示“提取中/生成中/合并中”，不编造百分比。

前端创建任务后返回 202；每 2 秒查询，页面隐藏后降到 5～10 秒；离开页面停止轮询但不自动取消任务，重新进入可恢复查看。

运行取消先写 cancelRequested，再中断上游 HTTP 调用，确认工作线程退出后置 CANCELLED。未退出时显示“正在停止”。最终成功与取消通过原子状态条件竞争，禁止取消后又覆盖为成功。

创建任务使用用户作用域的 Idempotency-Key；同键同输入返回原任务，不增加调用；同键不同输入返回 409。不同用户同键互不影响。键和请求摘要保留 24 小时；清理时明确这一去重窗口。

### 8.2 故障处理

- 外部请求不持有数据库事务或用户行锁；先登记任务、释放事务，再调用，最后短事务保存结果。
- 不对可能已被供应商接收的生成请求自动重试；网络超时可能已经计费。用户主动重试创建新任务并显示提示。
- 429、5xx 记录可重试状态及可用 Retry-After 信息，不在后台无限重发。
- 服务重启后，原 RUNNING 任务标记失败 `INTERRUPTED`，不自动重复收费请求；QUEUED 任务重新鉴权和检查配置后才继续。
- 调用已完成但落库失败时，不重新调用供应商。允许重试保存仍在内存中的结果；进程丢失时标明结果不可恢复、用量可能未知。
- 修改模型配置使排队任务 STALE；更换密钥、停用连接或账号时取消相关任务。连接配置变更使用版本号避免混用新旧配置。

### 8.3 初始上限（实施基线，可由管理员下调）

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 每用户连接/模型 | 5 个连接、每连接 10 个模型 | 防止配置无限增长 |
| 用户并行/排队 | 1 个运行、5 个排队 | 超出返回可理解的限流提示 |
| 全站并行/排队 | 4 个运行、50 个排队 | 第一版单实例；明确公平调度 |
| 连接/单次调用/任务截止 | 10 秒 / 120 秒 / 10 分钟 | 任务内所有子调用合计受截止时间约束 |
| 单次响应体 | 2 MiB | 超出即终止读取 |
| 单任务模型调用数 | 最多 8 次 | 包含分段与合并 |
| 问题长度/历史 | 2000 字符 / 最多 6 轮 | 仍受上下文预算限制 |
| 单次输入文本/输出 | 最多 24000 字符 / 最多 2048 输出 token | 只是站点上限，较小模型需进一步减少 |
| 单用户每日上游调用 | 100 次 | 测试和每个子调用都计数，UTC 日界并在 UI 标明 |
| 缓存/任务结果/会话 | 30 天 / 7 天 / 最近活动后 30 天 | 正文派生数据不永久增长 |
| 用量记录/幂等记录 | 90 天 / 24 小时 | 不保留密钥和完整提示词 |
| 每用户 AI 派生数据 | 100 MiB | 独立额度，超限拒绝新内容并提供清理入口 |

字符数不等于 token。预算优先使用经过验证的模型 tokenizer；未知模型以保守估算和余量限制，界面显示估计性质，不能承诺适配任意上下文窗口。

用量分别记录供应商返回的 input/output/total token、估算值和 UNKNOWN。未返回用量时不写 0；估算费用只在用户配置单价后显示，不将估算当作供应商账单。每日调用额度在发起请求前原子预留，避免并发绕过。

## 9. 数据模型草案

以下为实现契约和字段草案，具体 SQL 在对应阶段编写；不要提前一次性建立后续所有表。ID、时间、布尔字段和外键风格遵循项目现有约定，两种数据库均要验证。

| 表 | 核心字段 | 约束/索引 |
| --- | --- | --- |
| `ai_connection` | id、user_id、name、protocol、base_url、secret_cipher、key_id、enabled、config_version、last_test_status、created_at、updated_at | `(user_id,id)` 查询；密钥只在此持久化 |
| `ai_model` | id、user_id、connection_id、name、model_id、purpose、context_limit、max_output、output_param_mode、enabled、config_version | 校验 connection 同用户；purpose 枚举 |
| `ai_preference` | user_id、default_chat_model_id、未来 default_embedding_model_id | 用户一行；默认模型必须属于本人且用途正确 |
| `ai_consent` | user_id、connection_id、destination_fingerprint、notice_version、accepted_at | 目的地或告知范围变化时失效 |
| `ai_document` | id、user_id、file_id、revision、extractor_version、status、coverage、truncated、bytes | 同用户/文件/修订/提取器唯一 |
| `ai_chunk` | id、document_id、ordinal、text、locator、content_hash | `(document_id,ordinal)` 唯一；locator 是受控 JSON |
| `ai_task` | id、user_id、kind、file_id、revision、model_id、config_version、status、request_hash、idempotency_key、cancel_requested、stage、error_code、timestamps | 用户状态时间索引；用户幂等键唯一；不保存密钥 |
| `ai_artifact` | id、user_id、task_id、cache_key、kind、body、sources、coverage、expires_at | 用户缓存键唯一；读取重新鉴权 |
| `ai_call` | id、user_id、task_id、call_index、model_snapshot、status、actual_usage、estimated_usage、latency、error_code、created_at | `(task_id,call_index)` 唯一；不记录原始请求体 |
| `ai_daily_usage` | user_id、utc_date、reserved_calls、started_calls | 原子预留/结算；唯一用户日期 |
| `ai_conversation`（v0.2） | id、user_id、file_id、revision、model_id、status、created_at、updated_at | 用户与文件修订索引 |
| `ai_message`（v0.2） | id、conversation_id、role、content、task_id、status、created_at | 会话顺序；重试不产生重复成功回答 |
| `ai_citation`（v0.2） | message_id、source_id、file_id、revision、locator、excerpt | 来源必须属于当前会话允许范围 |

AI 派生数据额度按数据库中保存的 UTF-8 内容和向量载荷估计量计量，不伪装成源文件磁盘占用。新增、替换、过期清理应原子更新计数，定期校准；达到额度先清理过期缓存，不能删用户源文件。

连接删除：拒绝仍运行任务或先完成取消；清理凭据、清空默认选择。历史任务保留无凭据的模型名称快照；数据库外键使用显式清理/SET NULL 方案，不能因外键阻止撤销密钥。

文件永久删除：在业务事件中安排派生数据清理，并定期扫描补偿；访问鉴权立即阻止读取，不能等待异步清理才生效。v0.3 同样适用于外部向量库。

## 10. API 契约

统一前缀 `/api/ai`，遵循当前 Cookie 登录、CSRF 和 Problem 错误响应。所有 ID 均验证归属；越权资源统一返回不存在。

| 方法与路径 | 用途 | 关键约定 |
| --- | --- | --- |
| GET `/capabilities` | 站点开关、允许能力、限制 | 不暴露内网管理配置和密钥 |
| GET/POST `/connections` | 列出/创建本人连接 | POST 不发起外部请求 |
| PATCH/DELETE `/connections/{id}` | 编辑/撤销连接 | 乐观版本号；密钥更新语义见第 3 节 |
| DELETE `/connections/{id}/credential` | 清除密钥并停用 | 取消关联任务，返回配置状态 |
| GET/POST `/models` | 列出/创建本人模型 | 连接归属和用途校验 |
| PATCH/DELETE `/models/{id}` | 编辑/删除模型 | 更新配置版本、维护默认值 |
| POST `/models/{id}/test` | 发起短测试任务 | 202，计数，接受幂等键 |
| GET/PUT `/preferences` | 默认聊天/向量模型 | 不允许选择他人或停用模型 |
| POST `/consents` | 记录外发知情确认 | 后端生成/核对目的地指纹 |
| POST `/files/{id}/summaries` | 创建摘要任务 | modelId、expectedRevision、range、language、forceRefresh |
| POST `/files/{id}/tag-suggestions` | 创建标签建议任务 | 不修改真实标签 |
| GET `/tasks/{id}` | 状态和已授权结果 | 200；返回阶段、覆盖范围、脱敏错误 |
| GET `/tasks` | 当前用户任务列表 | 分页，不能无界返回 |
| POST `/tasks/{id}/cancel` | 请求取消 | 202 或已存在终态；幂等 |
| GET `/usage` | 当前用户用量 | 时间范围上限 90 天；未知值明确展示 |
| DELETE `/artifacts/{id}` | 删除本人生成内容 | 不删除源文件 |
| POST `/conversations` | v0.2 创建会话 | 绑定 fileId、revision、modelId |
| GET/DELETE `/conversations/{id}` | v0.2 查询/清除会话 | 文件和会话双重鉴权 |
| GET `/conversations` | v0.2 会话列表 | 本人、分页、可按文件筛选 |
| POST `/conversations/{id}/messages` | v0.2 提问 | 202 返回 taskId；每会话仅一个生成任务 |

成功创建任务返回 `taskId、status、pollAfterMs`；缓存命中可直接返回 `status=SUCCEEDED、cached=true`，但同样验证文件权限和修订。

错误码至少覆盖：`AI_DISABLED`、`AI_NOT_CONFIGURED`、`AI_ENDPOINT_BLOCKED`、`AI_CONSENT_REQUIRED`、`AI_AUTH_FAILED`、`AI_MODEL_UNSUPPORTED`、`AI_UPSTREAM_RATE_LIMITED`、`AI_TIMEOUT`、`AI_CONTEXT_TOO_LARGE`、`AI_NO_TEXT`、`AI_PARTIAL_CONTENT`、`AI_REVISION_CHANGED`、`AI_QUOTA_EXCEEDED`、`AI_CANCELLED`、`AI_INTERRUPTED`。

HTTP 约定：输入非法 400；未登录 401；禁用能力/未同意 403；资源不存在或他人资源 404；版本/幂等冲突 409；本站限流 429；上游失败 502；上游超时 504。异步执行失败通过 task.status/errorCode 表达，不把状态查询本身伪装成失败 HTTP。

## 11. v0.3：语义搜索与文件夹知识库

### 11.1 先确认向量模型

向量模型将文本变成可比较的向量，聊天模型负责组织答案。聊天 API 测试成功不能代表向量能力可用；v0.3 新增 EMBEDDING 配置及单独测试，检查向量维度、数量、有限数值和输入上限。

用户只配置聊天模型时仍可使用摘要和单文档问答；语义搜索入口说明需要额外配置。不能用另一个人的向量连接或平台默认连接补齐。

### 11.2 存储选型关口

实施 E01 时用实际个人资料规模验证外部向量服务与小规模本地存储方案，记录维度、索引体积、检索耗时、内存、备份恢复复杂度。以可部署、用户隔离、可删除和可备份为优先条件，再确定依赖和版本；在此之前不修改 Docker 服务。

最少基准集：100、1000、10000 个文本块，各 20 个已知答案查询，记录实际机器配置和 p50/p95 延迟。先用 1000 块 p95 ≤ 1 秒作为候选验收目标；未达到时依据实测明确限制，不编造容量承诺。

### 11.3 索引生命周期

- 用户显式选择文件或文件夹，展示解析范围和预估调用，再启动索引；首版知识库只覆盖创建时选定快照。
- 新上传或修改文件显示“需要更新”，用户显式增量更新；不会未经许可自动产生向量费用。
- 索引身份包含 userId、fileId、revision、chunkId、embedding 模型 ID/维度/配置代次、提取器与切块版本。
- 更换向量模型或维度建立新索引代次，不能混合比较；全部完成前不把半成品标记可用。切换成功后再清理旧代次。
- 查询时先施加用户和知识库范围过滤；获取片段后再核对文件最新状态。不能先全库取 topK 再仅靠前端删除他人结果。
- 文件移出所选目录、进入回收站、永久删除或版本变化，立即从可用范围中排除；后台清理可延迟，访问控制不可延迟。
- 查询向量与文档向量必须来自相同模型/维度/代次；不匹配时拒绝并提示重建。
- 索引任务可取消，重启不盲目重发已计费批次；批次有稳定 ID 和持久完成记录。
- 所有向量外发同样使用本用户连接、网络策略、配额和费用提示。

### 11.4 检索与答案

保留现有文件名、标签和正文搜索。新增“语义搜索”模式，返回匹配文件、相关片段和位置，不让 AI 编造路径。

知识库问答先检索，再组织答案；引用可跨文件，并显示不同来源间的冲突。初版 topK 建议 6，实际片段总量仍由上下文预算决定。质量提升顺序：提取质量 → 切块 → 查询范围 → 混合检索 → 必要时重排序，不先堆多代理流程。

v0.3 再定义 `ai_knowledge_base`、成员快照、索引代次和批次表，以及 `/knowledge-bases`、`/index-jobs`、`/semantic-search`、知识库会话接口。沿用第 8～10 节任务和权限契约，实施 E01 完成后补充准确字段与接口，不凭未经验证的存储方案冻结 SQL。

## 12. 后续增强的边界

### 12.1 版本变化摘要

选择两个仍有访问权限的文件版本，先做确定性的文本差异，再让模型解释修改点。展示增加、删除、调整及两边位置，避免仅把两个长文档整体塞入模型。版本已经删除或超出范围时明确提示。

### 12.2 智能整理

输出建议名称、标签、目标目录和理由；用户逐项选择后，服务器重新校验源修订和目标权限，调用现有操作服务。批量提交展示冲突和部分失败。第一版整理只做预览与确认，不引入模型自主操作循环。

### 12.3 OCR、图片理解、音视频

作为独立需求分别评估，不默认包含在本计划首轮。需明确模型能力、外发原始媒体的同意、体积上限、费用、图片定位和新的测试集。OCR 成功应标记为识别文本，不能混淆为原生文本层。
