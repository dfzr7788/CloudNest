## 本轮实现说明

- [Agent Runtime 与审批](agent-runtime.md)：运行复用 `ai_task(kind=AGENT)` / `ai_call`。
  六轮模型、八次工具、从创建起两分钟、累计保守预算 32768、48 KB 结果；无隐式付费重试。
  成功工具参数与事实、拒绝摘要、模型推断和计费记录分别可查；失败/重启保留证据并标记停止。
- [同步协议与开发服务](sync.md)：默认生产不创建新表；开发配置加载 H2/MySQL V19/V20。
  变化 feed 明确为协调后的最终状态，不是完整操作审计；旧游标要求重取快照但保留本地基线。
- [Windows 客户端](../clients/windows-sync/README.md)：命令行、桌面目录选择、选择性传输、状态/冲突记录、
  用户级 Start 菜单安装入口。凭证不落 SQLite。下载不覆盖提交瞬间新出现的本地文件；原版本保留在回收目录。
- 节点中心新增“操作审批”和“资源拓扑”；批准只表示提交任务，不制造复制/校验完成状态。
  模型没有批准接口、任意命令或对象存储写工具。

## G0 发布门槛

2026-10-20 用户确认：暂无可用的真实双机与 1GB VPS 隔离测试环境，保留以下发布门槛；不以本地 fixture 或单机模拟替代真实验收。

- [ ] 本次提交完整远端 CI 通过。
- [ ] Docker Hub 可访问后，在隔离项目执行源码新装、预构建镜像导入及健康检查。
- [ ] 隔离恢复 MySQL、本地文件、S3 对象、签名密钥、版本和分享，并实际读回验证。
- [ ] Garage 双机独立读回与 SHA-256，节点下线/恢复、迁移、副本读取、所有副本不可用及对象损坏测试。
- [ ] 迁移运行中重启/取消，不清理唯一有效对象、不报告伪成功。
- [ ] 真实 1GB / 25GB VPS 内存、OOM、临时磁盘峰值、Range 延迟与并发测量。
- [ ] 建立成套备份与回退基线，并实测恢复；数据库迁移不能仅回滚 JAR。

原方案要求“所有生产数据模型变更需要基于经过稳定验收的 2.0”。因此 G0 未完成前，
新增同步/审批表只放在独立开发迁移目录，不加入默认生产 Flyway，也不将当前工作区标记为整个 2.1 完成。
剩余开发项与全部真实验收继续属于本任务范围。
