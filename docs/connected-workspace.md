## 本轮新增：只读诊断工具

管理员可在“节点中心 → 只读诊断”手动读取节点健康、容量与预留、健康事件、活动任务和调度策略。
工具默认关闭，通过 `AGENT_TOOLS_ENABLED=true` 启用，不依赖 `AI_ENABLED`，不调用模型或修改业务数据。
结果明确显示数据库来源、查询时间与调用标识，节点状态可能过期，容量预算不等于远端实测余量。

本轮新增 10 项后端测试，覆盖独立授权与撤销、只读行为、参数、请求/结果大小、重复 JSON、CSRF 和限流。
完整后端回归 143 项通过（1 项需要独立 MySQL 的旧库升级测试仍跳过），前端类型/生产构建及四项浏览器测试通过。
没有新增 Flyway 迁移。成功调用元信息进入现有服务日志，完整 Agent run/step/approval 持久化仍未实现。
配置、API、行为边界与后续步骤见 [只读工具说明](agent-tools.md)。

## G0 发布门槛

2026-10-20 用户确认：暂无可用的真实双机与 1GB VPS 隔离测试环境，保留以下发布门槛；不以本地 fixture 或单机模拟替代真实验收。

- [ ] 本次提交完整远端 CI 通过。
- [ ] Docker Hub 可访问后，在隔离项目执行源码新装、预构建镜像导入及健康检查。
- [ ] 隔离恢复 MySQL、本地文件、S3 对象、签名密钥、版本和分享，并实际读回验证。
- [ ] Garage 双机独立读回与 SHA-256，节点下线/恢复、迁移、副本读取、所有副本不可用及对象损坏测试。
- [ ] 迁移运行中重启/取消，不清理唯一有效对象、不报告伪成功。
- [ ] 真实 1GB / 25GB VPS 内存、OOM、临时磁盘峰值、Range 延迟与并发测量。
- [ ] 建立成套备份与回退基线，并实测恢复；数据库迁移不能仅回滚 JAR。

原方案要求“所有生产数据模型变更需要基于经过稳定验收的 2.0”。因此 G0 未完成前，
不将 Agent / 同步草案表直接写入生产 Flyway，也不将当前工作区标记为 2.1 完成。
这些后续模块仍属于用户要求的升级范围，需在门槛完成后继续实施。

## 复验入口

```powershell
.\scripts\dev.ps1 test
python scripts/check-deployment-artifact.py --require-artifact
python scripts/check-api-contract.py
cd cloudnest-web
npm run check:i18n
npm run test:i18n
```

产物检查前先执行 Maven `verify` 或 `package`；`dev.ps1 test` 本身只执行后端测试及前端构建。
Docker 恢复演练脚本 `scripts/test-compose.py` 是 CI 专用，不能直接对已有部署运行。
真实部署与回退按 [部署文档](deployment.md) 和 [双节点恢复](deployment-dual-node.md) 执行。
