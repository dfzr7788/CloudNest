# 实施决策

## ADR-001：开发与生产数据库

生产使用 MySQL，开发默认使用文件型 H2（MySQL 模式）以便无需修改本机数据库即可运行。自动化集成测试使用独立内存 H2；真实 MySQL 的验证独立记录。迁移脚本分别针对 H2/MySQL，表结构保持等价。

## ADR-002：统一用户可见条目

以 `drive_entry(kind=FILE/FOLDER)` 统一替代计划中的 `file_folder` 与 `file_info` 两张表。保留独立 `file_blob`；此调整让目录树遍历、删除批次、分页与恢复共享一致的模型。文件/文件夹允许同名，约束包括 kind；NFC 规范化，名称大小写敏感。用户账号不区分大小写。

## ADR-003：事务与运行实例

采用单个后端实例。事务通过用户行锁串行化该用户元数据与配额变更；分片写入、完成、取消和清理在会话锁下进行。耗时传输不持有数据库用户锁。存储写入不能由数据库事务回滚：使用持久会话、READY 状态、宽限清理与失败重试实现补偿。

## ADR-004：版本来源

Java 21 与 Spring Boot 3.5 系列兼容性参考 [Spring 官方要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)；MyBatis-Plus 使用 [官方 Boot 3 starter](https://baomidou.com/getting-started/install/)；Node 版本参考 [Vite 官方要求](https://vite.dev/guide/)。最终可用版本以构建成功与锁文件为准。

## ADR-005：详细记录

按用户补充要求，每项预期结果记录在 acceptance.md，并在执行日志和测试报告中填写实际证据。代码存在、编译通过、功能测试通过、外部环境部署通过分别记录，不能互相替代。

## ADR-006：受控 PDF 渲染

使用 PDF.js 6.4.299 与独立 Worker 渲染画布并翻页，按需加载组件；保持后端授权和 Range 读取，不依赖用户浏览器的 PDF 插件。根据该依赖的实际 engines 字段，前端开发要求 Node 22.13+ 或 24+。

## ADR-007：外部部署与测试边界

官方 MinIO 社区二进制分发返回 410，默认部署采用已实测的本地存储。MinIO SDK 与迁移通过 S3 HTTP 模拟契约验证，真实服务验收单独保留。当前机器没有 Docker 和目标 Linux/证书，交付 Compose/TLS 配置与手册，不将其计为已部署。

## ADR-008：历史与固定分享

`file_version` 只保存非当前内容。提交新版本时，把已上传的同用户独立条目内容转为目标当前内容，原当前内容进入历史，来源条目被消费；容量总和不变。恢复是交换当前与所选历史，使用 revision 检测并发。历史最多 20 份，不自动删除旧内容。

单文件分享持有创建时 blob；目录分享动态校验子树。blob 回收同时检查当前条目、历史和固定分享；撤销/过期分享释放固定引用。ZIP 创建时记录文件修订号，下载前复核。audit/recount 同步计入历史逻辑容量。

## ADR-009：无状态 Cookie 与 CSRF

无状态认证在每次请求重新建立身份，不应因此每次执行 CSRF 的“新登录”令牌清除。明确配置 CSRF 的会话认证策略，保留每次写入的令牌校验；登录、注册、退出显式清除旧令牌。真实 Chrome 用例覆盖并行读取、原令牌写入成功和无令牌写入被拒绝。

## ADR-010：本轮部署授权范围

用户选择部署至现有服务器后，又明确“你先做，后面我自己配吧”。因此完成本机升级、验证及可配置部署资料，不猜测服务器或修改远程主机。外部真实环境仍保留待验收。
