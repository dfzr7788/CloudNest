## E007：强制重启与持久性修复

- 预期：1 GiB 共 128 片，上传前 64 片后强制结束进程，重启仍应查询到 64 片。
- 首次实际：重启后只恢复到第 50 片（51 片），最近成功响应的部分提交未落盘；原结果保存在 evidence/lifecycle-first-failure.json。
- 原因：H2 默认延迟写入，在 Windows 强制结束进程时最近的提交可能丢失。
- 修复：开发文件数据库显式配置 WRITE_DELAY=0；验证脚本与启动文档同步。恢复逻辑仍以服务端记录为准，丢失记录的分片允许重传。
- 另一次环境问题：沙箱内 Mockito 动态代理附加通道被拒绝，测试停在启动阶段；停止该测试并在正常权限下复测。此问题不计为业务测试通过。
- 状态：修复已实现，等待复测结果补录。
