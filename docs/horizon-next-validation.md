## 真实 Garage 2.4.1

启动本机 Docker Desktop，使用已缓存的 `dxflrs/garage:v2.4.1` 镜像，在回环端口创建两个独立 Garage 实例，使用新数据卷、新随机应用密钥和新测试桶。后端和数据库同样使用专用临时目录。未连接生产数据库或生产桶。

实际执行并通过：

1. 配置 region=garage，执行认证读写/校验探测。
2. 上传并读取 156019 字节测试内容，直传未开启时保留分片代理计划。
3. 创建目录快照、复制到第二实例，验证逻辑异域副本状态。
4. 执行迁移并校验新主存储内容。
5. 删除目录并永久清空源目录的回收站记录。
6. 停止当前主存储的测试容器，从另一实例读取历史内容。
7. 按恢复预览执行快照恢复，读取恢复副本，验证 SHA-256 对应内容一致。
8. 恢复测试容器，结束后停止本轮测试服务。

两个实例都位于同一台物理开发机，故障域是测试模拟；不能算作独立物理设备的副本验收。测试过程中一次范围过大的其他节点停用步骤被自动审批拦截，已移除。最终脚本未停用其他 S3 节点，容器操作仅针对本轮带专用标签的测试容器。

## 尚未完成的发布门槛

- Windows WebClient 实际盘符挂载、编辑保存、文件大小限制、断网与卸载行为。已验证脚本语法和安装分发，没有自动修改用户机器的服务、注册表或盘符。
- 原生 WinFsp、可配置离线缓存、待同步/待写回管理及原生虚拟磁盘冲突体验；当前实现是方案第一阶段的 WebDAV MVP。
- 真实 Garage 的 HTTPS/CORS/POST-policy 公网直传；当前已有独立协议测试及默认关闭/代理回退逻辑，真实 Garage 验证覆盖的是代理读写与恢复。
- 两台独立物理机器、校园网/公网故障、低内存、长时间负载和生产备份演练。
- 客户端加密保险箱按 P2 延后；没有声明零知识加密。
- 旧迁移任务仍保留原任务表与兼容状态，未完成全部历史任务物理存储的统一迁移。

因此目前可以交付开发预览和本地测试包，尚不能将联合执行方案的全部正式版验收项标为完成。使用见 [Horizon Next](horizon-next.md)，接口见 [API](horizon-next-api.md)。
