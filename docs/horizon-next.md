# CloudNest Horizon Next：2.2 / 2.3 开发说明

本分支在本地 2.1 代码上增量实现 Data Resilience 和 Distributed Workspace。当前为开发预览，不能将本机测试等同于生产发布验收。未执行生产迁移、部署或清理现有服务器数据。原生 WinFsp 客户端及客户端加密保险箱不包含在此次实现中。

本轮实际执行结果见 [本地验证记录](horizon-next-validation.md)，包括 H2、MySQL、真实 Garage 2.4.1 容器、轻量节点与浏览器验证，并逐项列出尚未完成的发布门槛。

## 使用入口

登录后侧栏的「数据保护」提供目录快照、历史树、相对当前状态的新增/修改/删除/移动比较、恢复预览、单文件或子树恢复、策略和任务控制。「显示所有历史目录」可以找回已删除甚至已清空回收站的历史目录。恢复目标由当前所选目录决定，恢复始终创建副本，不覆盖当前唯一修改。

「团队空间」提供创建、一次性邀请、成员角色、目录 ACL、文件浏览、分片上传、同名版本更新、移动、删除、团队回收站、空间配额、存储贡献及审计。团队管理员可以创建团队快照和恢复任务，以及对所选文件提交迁移或异域副本任务。

系统管理员在「数据保护」配置定时巡检、流式限速，查看损坏或不可用对象、规则分层建议，并接入已经通过团队审核的贡献节点。原有节点中心仍负责全局健康、容量预算、异域副本状态和迁移调度。

## 数据与任务约束

- 快照只复制元数据，引用稳定的 `file_blob.id`；物理位置变化由既有迁移服务维护。当前文件、历史版本、分享和快照任一仍在引用时，都不能回收对象。
- 配额按逻辑引用计费：每个快照的文件总大小计入配额，恢复副本另外计费。物理对象可去重。删除源文件只释放源引用的逻辑配额；删除快照才释放快照配额。维护工具的审计和重算采用相同规则。
- 单次快照最多 20000 项，每个归属账户最多 500 个快照。定时策略每轮处理最多 20 个目录，按保留份数清理；被可重试恢复任务引用的快照不能清理。配额不足时保留旧数据并报告错误。
- 普通预设沿用版本和回收站；重要/归档预设请求异域双副本，并可配置快照周期与保留数。实际保护必须按节点健康和副本校验结果判断。归档的独立备份需要使用现有备份流程另行配置。
- 恢复和巡检共用 `resilience_task`，状态为 `QUEUED → RUNNING → COMPLETE / FAILED / CANCELLED`，另有 `PAUSED`。每项提交与进度在同一事务内记录；重启后从已提交进度继续。幂等标识在用户和任务类型内唯一；巡检同时绑定范围指纹。
- 取消恢复保留已生成的恢复副本，不自动删除。目标目录被用户删除、配额变化或对象校验失败时，任务明确失败，快照保持引用保护。失败任务可重试或取消。
- 迁移和副本修复复用既有 `MigrationService` / `storage_job_item`，恢复和巡检不再实现一套复制引擎。旧迁移任务的 `INTERRUPTED` 状态继续兼容；尚未将所有历史任务表替换成一个物理表。
- 巡检每次执行一个物理对象，以 64 KiB 缓冲区读取、默认 8 MiB/s、单工作线程；按节点、归属账户或目录筛选。单批最多 20000 个对象、40000 个物理副本。暂停/取消在读取和限速间检查。损坏对象不删除；只有重新校验了可用副本后，才通过已有迁移服务请求修复。没有有效副本时记录 `NO_VALID_REPLICA`，阻止把已知损坏的唯一对象继续作为正常下载内容。

## 团队权限与配额

团队文件属于独立的不可登录资源账户，不属于任何成员的个人根目录。原有个人、分享、同步和 Agent 文件 API 仍按个人归属检查，因此不能通过团队文件 ID 绕过授权。资源账户即使被系统管理员重设密码，也被交互式登录明确排除。

| 角色 | 权限 |
| --- | --- |
| Owner | 文件、成员、配额与资源管理；不可被普通成员移除或变更角色 |
| Admin | 团队文件、目录授权、邀请、快照与节点审核；不能授予或修改其他 Admin |
| Editor | 授权范围内上传、版本更新、移动、新建与移入回收站 |
| Viewer | 授权范围内浏览和读取 |
| NONE + Contributor | 贡献存储，不具有团队文件读取权 |

Contributor 是独立布尔授权，可与文件角色组合；Owner 可单独切换自己的贡献授权。ACL 的 `READ / WRITE / DENY / INHERIT` 用于收紧角色默认权限，沿整个祖先链生效；不能通过子目录授权扩大父目录或角色权限。管理员负责管理整棵团队目录。目录移动、删除会检查其子树，防止携带被禁止修改的子内容。

团队行锁序列化成员/ACL 变更和写入提交；每个分片、完成操作都会重新授权，上传中途降权会立即阻止后续提交。上传会话绑定发起成员，其他成员不能借用会话。邀请单次使用、最长七天，令牌只存哈希，可以撤销。成员移除前需停用其已接入的贡献节点。

团队配额从 Owner 的可用个人配额划拨，总配额不凭空增加；调整配额须满足双方的已用和预留空间约束。团队审计记录真实操作发起人，不把内部资源账户当成人员身份。

## 轻量存储节点

见 [节点安装与目录边界](../clients/storage-node/README.md)。节点使用受控私网或 HTTPS，不需要数据库凭据、不执行控制中心下发的 Shell 命令。只实现对象 PUT、GET、HEAD、Range、DELETE 与健康检查。

流程：团队管理员授予 Contributor → 成员登记目录节点 → 团队管理员审核 → 系统管理员检查地址和物理故障域并执行认证读写探测 → 节点开始心跳 → 调度允许分配。

贡献仅供所属团队资源账户使用。跨团队和个人任务均不能选择该目标。节点容量预算不能超过成员声明的授权上限，节点程序还执行独立的磁盘容量限制。超过 120 秒未收到心跳、成员授权撤销或节点健康失效时停止新任务。停用贡献不自动删除已有数据；已有读取按物理副本和节点实际在线情况决定。

磁盘原始容量不等于副本保护后的可用容量。故障域必须对应真实物理设备或共同失效风险；程序无法自动证明两个地址位于不同物理机器。

## 传输与规则建议

下载在直连前进行短时 CORS / Range 能力探测，失败时回到原有代理地址；每次点击重新取得短期授权。浏览器下载开始后的网络中断仍依赖浏览器 Range 行为及重新授权，不声称接管浏览器的整个下载状态机。

公网 S3 上传原型默认关闭。节点中心中配置 HTTPS 公开地址、开启直连和「允许短期公网直传原型」，并配置服务端桶的 CORS / POST-policy 支持后，最多 100 MiB 的文件可使用 60 秒 POST 授权。策略绑定唯一暂存 key 和精确内容大小。Garage/供应商不支持 POST、CORS 失败或授权到期时，自动使用同一个分片代理会话继续。

服务端先将远端暂存内容限量落盘并核对 SHA-256，再导入已有分片/合并/发布流程；正式对象使用不同 key。持有尚未过期的上传签名不能覆盖正式文件。坏内容不会写入分片记录。暂存对象在签名失效并经过等待期后才清理，失败时保留容量预留。该原型仍有服务端验证与再次写入开销，不代表消除了服务器读流量。

冷热规则列出 90 天未访问文件和可靠性合格的候选节点；不自动搬迁。现有 Agent 增加三个只读工具：`get_resilience_health`、`get_team_capacity`、`get_migration_candidates`，都复用已有工具白名单、管理员权限、结果大小和调用次数限制。不会返回成员凭据或文件正文；实际迁移仍需经过已有人工审批与确定性服务。

## Windows 盘符 MVP

在账号安全中创建独立 WebDAV 应用密码，然后在 Windows PowerShell 中运行：

```powershell
.\clients\windows-sync\mount.ps1 -Server https://cloud.example.com/ -Drive N
```

脚本交互读取用户名和应用密码，使用 Windows WebClient / WebDAV Redirector 映射盘符。密码不放入命令行参数，不保存 S3 管理密钥。卸载使用同一脚本的 `-Unmount`；卸载前需关闭文件并确认应用已保存。

WebDAV 是当前实现的第一阶段。原生 WinFsp、可配置离线缓存、待同步状态展示和安全写回队列尚未实现；当前使用 Windows 自带缓存/大小限制，不能声称支持可靠离线写入，也不能用此脚本替代既有同步客户端。团队空间当前通过 Web 使用，不通过个人 WebDAV 暴露。

## 数据库升级与验证

新增 V21（快照、任务、团队、贡献和节点属性）、V22（直传暂存票据）；扩大了对象、上传和维护任务的节点标识长度。V1–V18 内容未修改。V19/V20 的原始 2.1 迁移原样复制到规范迁移目录，保持校验和，避免先启动新版本再启用 `connected-dev` 时漏执行较低编号迁移。`connected-dev` 现在只切换能力开关，加载同一条迁移历史。

自动化验证入口：

```powershell
.\scripts\dev.ps1 test
python scripts/test-storage-node.py
python scripts/test-sync-client.py
python scripts/check-api-contract.py
python scripts/check-publication.py
```

`ResilienceWorkspaceTest` 验证千文件快照、配额、清空回收站后恢复、幂等与中断重试、跨用户与团队 ACL、上传中途撤权、节点审核以及实际轻量节点进程的迁移/损坏修复/离线回退。`StorageContractTest` 验证 S3 适配协议、POST-policy 大小绑定和直传暂存与正式对象隔离；它是协议夹具，不是真实 Garage 验收。

真实浏览器验收见 `resilience-workspace.spec.ts`，仅在设置 `CN_NEXT_FIXTURE` 并指向隔离测试服务器时运行。尚需真实 Windows 盘符读写/大文件/断网测试、真实 Garage 直传兼容性、跨物理机器故障、低内存与长时间稳定性验收。加密保险箱按方案延后，未声称零知识加密。
