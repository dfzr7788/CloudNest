# CloudNest 2.0 Horizon

2.0 将现有 Spring Boot + Vue 网盘扩展为多节点资源池。本次代码版本为 `2.0.0-rc.1`；真实 Garage 双机故障、隔离恢复和 1GB 主机压力验收通过后才能发布稳定版。客户端分片仍经过业务服务器；没有引入客户端直传、冷热分层或多业务实例。

## 使用方式

管理员从侧栏进入「节点中心」，或打开 `/admin/nodes`。

1. 在节点总览新增 S3 兼容节点，填写内部地址、桶、区域和凭据，执行完整读写检测。
2. 配置管理员预算、写入权限和管理状态。预算是允许 CloudNest 使用的额度，不是远端磁盘探测值。
3. 在调度策略配置故障域、可靠性、优先级和成本。相同机器、共享磁盘或同一故障风险应填写相同故障域。`unassigned` 不参与异域保护。
4. 选择调度模式并保存。升级保留手动模式与原默认后端，不自动移动已有文件。
5. 文件操作菜单或批量选择栏打开「存储与副本」，选择迁移主存储或创建异域保护副本。目录操作展开未删除的子文件，每次最多 200 个对象。

在单文件副本详情中可停止自动副本保护；这会取消复制任务并停止自动修复，保留已有数据。普通用户只能处理自己的文件。管理员可在节点中心查看及取消、重试全部文件任务。共享同一个内容对象的文件记录、历史版本或固定版本分享会共同使用迁移后的对象位置，迁移不会复制逻辑文件或改变权限。

## 调度与容量

支持 `MANUAL`、`CAPACITY`、`STABILITY`、`HIGH_AVAILABILITY`。规则先过滤停用、维护、暂停写入、健康异常、检测过期、未验证、预算不足及可靠性不达标的节点，再按预算余量、管理员可靠性、近期成功检测次数、优先级、成本和延迟评分。可靠性是管理员评级，并非统计意义上的可用性保证。未知容量不会当作无限可用空间。

上传初始化持有用户行锁与 `storage_guard` 行锁，在同一事务中选择并预留容量。创建会话后后端固定；续传不会重新调度。高可用模式先为两个故障域预留容量，主对象上传成功后提交异步副本任务。**上传完成不代表双副本已经完成**：以文件副本详情中的 `protected` 及后台任务结果为准。

调度记录给出选择策略、节点、分数、预算余量、可靠性及排除原因。现有直连下载仍需逐次授权；异常或检测过期节点不再签发新的直连地址。保护文件走代理读取，以便在发送响应前验证数据和选择有效副本。

容量分别统计：

- 用户逻辑占用：文件、历史版本、回收站等现有配额口径。
- 节点物理占用：主对象、保护副本、迁移保留对象，以及可能已写入的失败候选对象。
- 管理员预算及任务预留：在存储锁下检查，失败或取消的物理候选仍计费，不能因释放任务预留而丢失占用记录。

没有自动删除迁移来源。原有副本清理接口保留 120 秒安全等待期，并拒绝删除仍被上传、对象、副本记录或任务引用的数据。未被管理副本引用的来源保留对象，可由管理员检查后清理；保护副本不能用该接口删除。

## 迁移与副本

文件任务先登记物理候选，再复制、校验对象长度和 SHA-256，最后在短事务中更新引用。复制期间不持有节点全局锁。取消会立即阻止引用更新；正在进行的提供商请求可能需要等到完成或超时，其候选对象保留计账。服务重启将执行中的任务标为中断，管理员可重试。整节点迁移保留原入口，与文件任务互斥。

`file_blob.backend` 保留兼容性。增量迁移将历史主对象写入 `blob_replica`，初始状态为 `UNVERIFIED`，不会把数据库记录当作物理校验证据。新上传会读回验证主对象；创建保护副本会验证来源和目标。只有实际验证成功的副本才标记 `VERIFIED`。

保护读取先将候选对象流式写入受预算约束的临时文件，验证长度与 SHA-256，再向客户端提供完整文件或 Range。损坏对象标记为 `CORRUPT`；离线、过期及未验证的备用副本不参与读取。候选全部失败返回 `503 REPLICAS_UNAVAILABLE`，不返回虚假的成功或未经校验的数据。临时文件在流关闭时释放，重启清理遗留暂存。

这种验证需要主服务器暂存整个受保护对象，增加首字节等待和磁盘 I/O。暂存空间不足返回容量错误；没有使用内存缓存整文件。为重要文件按需开启保护，并在实际 1GB 主机上验证允许的并发和临时磁盘峰值。

后台每分钟轮巡校验一个受保护副本，并扫描一批保护对象；发现缺少异域在线副本时，从有效来源安排修复，失败后至少等待五分钟再自动尝试。健康恢复经过完整读写检测，已有两次成功恢复要求继续保留。副本全部不可用时等待节点或独立备份恢复。单实例调度线程池为 3，文件复制仅单工作线程，避免阻塞健康检测；该版本仍只支持一个业务实例。

## 升级和回退

1. 停写并创建一致性成套备份：数据库、所有本地和远端对象、配置、密钥、运行版本。
2. 使用隔离环境先升级副本。Flyway 新增 H2 V17 / MySQL V18，不修改既有迁移，也不替换原主存储字段。
3. 启动候选版本，检查旧文件、历史版本、分享、回收站和上传续传。配置故障域后再启用自动调度和保护。
4. 若需回退，恢复升级前的数据库与对象成套备份；仅切换旧镜像不是数据库回退。

成套备份清单新增副本记录与其后端引用；隔离恢复验证会核对副本清单。便携恢复只恢复逻辑内容到本地，重建未验证的本地主对象记录，中断原远端任务，保留双副本期望但不声称已保护。需要重新配置第二节点并完成校验。离线审计额外核验受保护的物理副本。

## 验证与正式发布门槛

可重复的代码验证：

```powershell
.\scripts\dev.ps1 test
python scripts/check-api-contract.py
python scripts/test-backup.py
python scripts/test-split-backup.py
# 在独立测试服务运行后执行
cd cloudnest-web
npx playwright test e2e/horizon.spec.ts
```

`HorizonTest` 覆盖解释性调度、并发预留、会话后端固定、不同故障域限制、双副本、Range 故障切换、全部失效、损坏副本修复、文件级迁移失败重试、运行中取消、重启中断和跨用户授权。测试中的提供商是受控故障注入，不代表真实 Garage 部署验收。`CN_HORIZON_DATABASE_URL` 可指向专用可丢弃 MySQL 数据库；测试会清理业务测试表，严禁使用生产数据库。

稳定版必须补齐并保存以下实测证据：

| 场景 | 必须验证 |
| --- | --- |
| 实际 A + Windows Garage B | 双端对象独立读回，长度与 SHA-256 一致 |
| B 关机、断网、恢复 | 停止分配、有效副本继续读取、完整检测恢复调度 |
| 两端对象损坏或不可用 | 明确失败，无内容损坏、权限绕过或假成功 |
| 迁移中断与重启 | 来源保留、候选容量记账、重试与取消一致 |
| 一致性备份隔离恢复 | 使用独立地址和数据卷恢复数据库、对象、密钥；验证分享、版本、回收站 |
| 实际 1GB 主机 | 在承诺并发下测量 RSS、OOM、临时磁盘峰值、上传/下载带宽与首字节时间 |

本地构建、模拟故障及协议测试不能替代这些环境验收。双副本不能防止误删除、数据库损坏或勒索事件，独立备份与恢复演练仍然必要。
