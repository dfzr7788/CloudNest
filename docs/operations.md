# 上线验收与日常维护

[文档中心](README.md) · [部署手册](deployment.md) · [系统更新](system-updates.md)

## 第一次上线

先使用合成文件完成下面的闭环，再导入重要数据。记录版本、部署方式和日期，分别记为通过、失败或未执行。

| 检查 | 操作与完成标准 |
| --- | --- |
| 服务 | `docker compose ps`；MySQL、Redis、server 健康，web 运行，首页及 CSRF 接口可访问 |
| 账号 | 创建管理员后登录；用邀请建立测试普通账号，确认没有公开默认密码 |
| 文件 | 上传文本、图片和较大文件；下载后比对 SHA-256；暂停再继续上传 |
| 分享 | 用未登录浏览器打开测试分享，确认提取码和下载设置；撤销后确认不可访问 |
| 删除恢复 | 删除测试文件后从回收站恢复，再次下载核验 |
| 团队 | 邀请测试成员上传，撤销成员后确认不能继续读取/提交 |
| 快照 | 对测试目录做快照，修改文件，再恢复副本，核对内容与目标目录 |
| 备份 | 创建并 verify 一份备份，在独立实例执行恢复，登录并校验文件 |

具体备份和恢复命令见[备份与恢复](deployment.md#备份与恢复)。快照、双副本、校验清单成功均不能替代整套恢复演练。

## 日常巡查

按实际使用频率检查剩余磁盘、节点健康、失败任务、最近备份和更新时间。上传临时数据、ZIP、历史版本、快照和远程对象导出都可能额外消耗空间。

```bash
docker compose ps
docker compose logs --tail=100 server web
df -h
```

安装了宿主机服务的服务器再检查：

```bash
systemctl status cloudnest-updater --no-pager
systemctl status cloudnest-backup.timer --no-pager
journalctl -u cloudnest-backup -n 80 --no-pager
```

未安装这些可选服务时，查不到对应 unit 不表示云盘故障。日志只在本机保存，分享前移除凭据、分享链接及私人文件信息。

## 升级检查

1. 阅读目标版本说明，确认当前部署支持的更新通道和架构。
2. 完成成套备份并校验，确认有足够空间保存旧数据和恢复实例。
3. 按[系统更新](system-updates.md)或[手动更新](deployment.md#更新项目)执行；保留失败阶段和受控错误信息。
4. 升级后重复登录、上传下载、分享和恢复检查，确认后台任务状态。

数据库迁移之后，不能仅切换旧镜像完成回退。发生故障按[排障手册](troubleshooting.md)定位，必要时恢复配套数据与程序版本。

## 性能与故障验证

性能结果应注明 CPU、内存、磁盘、网络、存储类型、文件数量/大小和并发数。优先测列表、搜索、上传、ZIP 和下载，记录耗时、错误率、CPU、内存及剩余空间。仓库提供 `scripts/download-benchmark.py`，参数可用 `python scripts/download-benchmark.py --help` 查看；只对授权的测试账号和固定数据集执行。

在独立环境模拟存储节点断开、上传中断及服务重启，核对任务状态和文件摘要；磁盘不足演练应使用独立受限测试磁盘，不填满生产系统盘。真实 S3、跨机器切换和长期负载必须在对应拓扑验证。本机测试不能推导生产容量上限。
